# 上游选择性回移工作流

本文件定义精简版 `CherryLover/sub2api` 跟随 `Wei-Shaw/sub2api` 上游时的长期筛选规则。目标不是同步全部上游功能，而是持续保持精简版的**主线网关能力**、核心兼容性、可靠性与安全修复。

## 1. 基本原则

每轮先更新并比较 `upstream/main`、`lite/main`，逐项审查上游新增提交；不得只按提交标题或 `feat` / `fix` 标签机械筛选。

精简版仍坚持“少功能、少依赖、少维护面”。与主线无关的产品功能、外围管理能力和独立业务模块可以不回移；核心转发链路需要持续跟进。

## 2. 主线能力：必须审查，默认应回移

以下变化属于主线，不得因为它是 `feat`、新功能或需要少量配套改动就直接跳过：

- **新模型 / 新模型版本支持**：OpenAI / Codex、Anthropic / Claude、Google / Gemini、xAI / Grok，以及精简版已经支持的平台出现新的主流模型、模型版本、thinking/reasoning 档位或正式替代型号。
- 模型目录、模型映射、别名、白名单、协议适配、请求/响应转换、模型发现。
- 新模型对应的计费价格、fallback pricing、token/reasoning/cache/image 等计费口径。
- 账号选择、调度、failover、限流、冷却、会话粘性、并发和重试等网关核心逻辑。
- OpenAI/Anthropic/Gemini 等主协议兼容性，以及精简版实际使用的上游接入路径。
- 核心安全、数据正确性、账单正确性、稳定性 bugfix。

### 新模型特别规则

发现上游新增模型能力时，必须单独列为“主线模型更新”核对，至少检查：

1. 模型 catalog / `/models` 暴露；
2. model mapping、alias、白名单和前端可选项；
3. 对应协议入口和转发路径；
4. thinking / reasoning / multimodal 等模型特性；
5. pricing / fallback pricing / usage 计费；
6. 相关单元测试、集成测试和兼容性测试。

若精简版当前缺少该新模型所依赖的一部分基础设施，**不能直接以“精简版没有依赖”为理由跳过**。应先判断能否做最小适配；如果完整支持会明显扩大精简版范围或存在架构冲突，则暂停该项并明确提醒用户，由用户决定是否引入依赖或调整范围。

换言之：**新主流模型能力默认进入候选回移集；有争议时提醒用户，而不是静默排除。**

## 3. 非主线能力：默认可以不回移

通常可以跳过：

- 支付、营销、邀请、赞助、商城等商业外围功能；
- 与网关核心无关的管理 UI 扩展；
- 精简版已明确裁掉的平台或业务模块的新功能；
- 大型审计/运营/报表功能，但不影响核心转发、计费正确性或安全；
- 实验性、特定客户定制或与当前支持路径无关的能力。

但如果这些提交同时包含主线 bugfix、新模型支持或核心协议修改，必须拆分审查，不能整包排除。

## 4. 需要用户确认的情况

出现以下情况时，在实施前或发现后立即向用户说明：

- 新模型支持需要引入较大的新基础设施或恢复此前裁掉的模块；
- 上游改变核心调度、计费、冷却、failover 等既有行为，且与精简版现有定制冲突；
- 一个提交混合主线能力与大量非主线功能，无法安全最小拆分；
- 回移会改变数据库 schema、公开 API 或现有用户行为，风险明显；
- 无法确认某项新模型/协议能力是否属于精简版预期支持范围。

记录中应给出上游 SHA、依赖、精简版现状、建议方案和风险，让用户做范围决策。

## 5. 实施与验证

优先选择最小回移，而不是整文件覆盖或机械 cherry-pick。发生冲突时保留精简版已有定制，只引入主线能力所需差异，并补充针对精简版的回归测试。

每批完成后：

1. `git diff --check`；
2. 运行可用的本地测试；
3. 推到个人 fork；
4. GitHub CI 必须覆盖 frontend、embed/build、unit、PostgreSQL/Redis integration、golangci-lint、部署脚本；
5. Security Scan 必须通过；
6. 失败则修复后重新跑最终 SHA；
7. 全绿后才创建到 `CherryLover/sub2api:main` 的 PR；
8. 不自动合并、不自动发版、不推镜像。

## 6. 每轮审查输出

每轮上游检查至少分为：

- **确定回移：主线能力 / 核心 bugfix**；
- **主线候选但需用户确认**；
- **非主线，暂不回移**；
- **精简版已存在或已等价修复**。

尤其必须显式列出本轮发现的所有新模型/模型版本，避免模型能力更新被普通 `feat` 过滤掉。
